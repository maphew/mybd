### 2. major — `procid.Verify` on Windows reports a terminated process as still matching
`/var/home/matt/dev/mybd/.worktrees/beads/review-psxg5-proxy-identity/internal/procid/procid_windows.go:29-43`

### 3. major — a root-ID mismatch bricks the workspace with no CLI recovery

### 4. major — `--force` can SIGKILL an unrelated live `bd` process

### 5. should-fix — control-listener accept errors tear down the entire proxy
`/var/home/matt/dev/mybd/.worktrees/beads/review-psxg5-proxy-identity/internal/storage/dbproxy/proxy/control.go:86-97` wired to `server.go:232-239`

### 6. minor — the client discloses the secret to a peer it has not yet authenticated
`/var/home/matt/dev/mybd/.worktrees/beads/review-psxg5-proxy-identity/internal/storage/dbproxy/identity/control.go:57`

### 7. minor — the control port is reachable by any local user; slot exhaustion is a cheap `bd` DoS

### 3. SHOULD-FIX — exclusive acquirers can be starved indefinitely by rolling shared holders
`internal/workspacegate/gate.go:327-371`

### 4. SHOULD-FIX — `0o600` gate files make cross-user shared roots unusable

### 5. MINOR — `AcquireAll` dedupe and ordering key on the raw path string
`internal/workspacegate/gate.go:447-458`

`forDir` canonicalizes symlinks via `EvalSymlinks` but not case: on macOS/APFS-CI and Windows, `EvalSymlinks` returns the caller's spelling. Two consequences:

- Dedupe miss: two `Gate`s that name the same file with different case do not collapse, so `AcquireAll(..., Exclusive, ...)` opens it twice and the second flock conflicts with the first — a guaranteed self-block for the whole wait budget.
- Ordering divergence: two processes spelling a shared path differently sort their gate sets differently, inverting the acquisition order. Bounded waits keep this a livelock rather than a deadlock, but both processes can burn their full budget and fail.

Fix: derive a comparison key that lowercases on `runtime.GOOS` in `{windows, darwin}` and use it for both the `uniq` map and the `sort.Slice` comparator (keep `g.path` as the open path).

## What's sound

I specifically tried to break the things you asked about, and these held up:

- **Lock ordering / deadlock.** Sorted canonical-path total order in `AcquireAll` is correct, and every wait is bounded, so even a caller who violates the "one AcquireAll" invariant gets `ErrBusy` rather than a permanent wedge. Only finding 5 perturbs this, and only into bounded livelock.
- **Crash recovery.** flock/`LockFileEx` are both released by the kernel on process death, and the sidecar is advisory-only with the lock as sole authority. **A dead holder cannot wedge future invocations** — `TestCrashReleasesLock` and `TestSpawnedChildDoesNotInheritGate` cover this directly, and the close-on-exec reasoning about a `dolt` child outliving its parent is correct.
