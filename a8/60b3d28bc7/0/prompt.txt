```go
// doltVersionAtLeast parses the first line of `dolt version` output (e.g.
// "dolt version 1.52.3\n", possibly followed by extra lines such as
// "database storage format: ..." when run inside a Dolt repo) and reports
// whether the trailing version token is &gt;= minVer, using numeric
// dotted-segment comparison. Returns false (fail closed) if the version
// cannot be parsed as a dotted sequence of non-negative integers.
func doltVersionAtLeast(versionOutput, minVer string) bool {
	firstLine := versionOutput
	if idx := strings.IndexByte(versionOutput, '\n'); idx &gt;= 0 {
		firstLine = versionOutput[:idx]
	}
	fields := strings.Fields(firstLine)
	if len(fields) == 0 {
		return false
	}

	got := strings.Split(fields[len(fields)-1], ".")
	want := strings.Split(minVer, ".")

	for i := range want {
		var g, w int
		var err error
		if i &lt; len(got) {
			if g, err = strconv.Atoi(got[i]); err != nil {
				return false
			}
		}
		if w, err = strconv.Atoi(want[i]); err != nil {
			return false
		}
		if g != w {
			return g &gt; w
		}
	}
	return true
}
```

Behavioral notes established by `internal/doltserver/gc_config_test.go:19-31`: `"dolt version dev\n"` → false; `""` → false; missing patch segment is treated as 0; dolt 2.x compares correctly against a 1.x floor (`"dolt version 2.2.2"` ≥ `1.52.1` → true).

Test escape hatch — `internal/doltserver/gc_config.go:98-104`: `ResetArchiveLevelSupportCacheForTest()`.

### 7b. The YAML config generation — where version sensitivity actually lives

Generation — `cmd/bd/proxied_server.go:444-475`:
```go
// renderProxiedServerConfig renders the managed sql-server config.yaml. When
// archiveLevelSupported is true it sets auto_gc_behavior.archive_level: 0,
// so this server's background auto-GC writes classic Snappy table files
// instead of zstd archives (gastownhall/beads#4986); auto-GC itself stays
// enabled (the sibling "enable" key is left unset, which Dolt defaults to
// true). When false, the key is omitted entirely — an older external dolt's
// own YAMLConfig struct may not have this field, and Dolt's config loader
// uses yaml.UnmarshalStrict, so an unrecognized key is a hard parse error at
// server startup rather than a silently-ignored one. Callers must gate
// archiveLevelSupported on doltserver.SupportsArchiveLevelConfig.
func renderProxiedServerConfig(port int, archiveLevelSupported bool) ([]byte, error) {
	host := proxiedServerListenerHost
	logLevel := string(servercfg.LogLevel_Info)
	yc := &amp;servercfg.YAMLConfig{
		LogLevelStr: &amp;logLevel,
		ListenerConfig: servercfg.ListenerYAMLConfig{
			HostStr:    &amp;host,
			PortNumber: &amp;port,
		},
	}
	if archiveLevelSupported {
		archiveLevel := 0
		yc.BehaviorConfig.AutoGCBehavior = &amp;servercfg.AutoGCBehaviorYAMLConfig{
			ArchiveLevel_: &amp;archiveLevel,
		}
	}
	body, err := yaml.Marshal(yc)
	if err != nil {
		return nil, err
	}
	return append([]byte(managedProxiedServerConfigMarker), body...), nil
}

const proxiedServerListenerHost = "127.0.0.1"
```

**The generated file is serialized from the *pinned module's* `servercfg.YAMLConfig` struct and then parsed by the *external binary's* own copy of that struct under `yaml.UnmarshalStrict`. That is the entire version contract, and today only one field (`archive_level`) is guarded.** Any future go.mod bump that adds a non-nil-defaulting field to `YAMLConfig` reintroduces the same refuse-to-start class of bug.

The self-identifying marker that makes reconciliation safe — `cmd/bd/proxied_server.go:29-40`:

### 7c. Other version-sensitive interactions in the proxied path

- **`CALL DOLT_GC('--archive-level', '0')` at shutdown** — `internal/storage/dbproxy/server/doltserver.go:377` calls `versioncontrolops.DoltGC` (`internal/storage/versioncontrolops/gc.go:13`). **This is NOT gated by `SupportsArchiveLevelConfig`.** An older external dolt server whose `DOLT_GC` stored procedure rejects `--archive-level` will fail here. ## Gaps most relevant to designing the contract

1. **No binary-path override exists** anywhere — five hardcoded `LookPath("dolt")` sites plus ~15 bare `exec.Command("dolt", ...)` sites. `ProxiedServerClientInfo` (`internal/configfile/proxied_server_client_info.go:13`) and the already-plumbed `--dolt-bin` flag (`cmd/bd/db_proxy_child.go:98`) are the natural insertion points; `internal/doltserver/doltserver.go:1535/1555/1558/1619` are the leaks that would need fixing.
2. **Two competing version floors, neither authoritative**: code says `1.52.1` (archive_level only), docs/CI say `2.2.0`/`2.2.2` (prose/test-only).
3. **The `dolt version` parser already exists and is well-tested** (`internal/doltserver/gc_config.go:103`, `gc_config_test.go`) but is private and single-purpose — extracting `parseDoltVersion` + a general `CheckDoltVersion(doltBin) (version, error)` is a small refactor.
4. **`bd doctor` is a no-op in proxied mode** (`cmd/bd/doctor.go:215`) and never checks for the dolt executable at all — the natural home for a version-contract preflight is currently unreachable in the mode that needs it.
5. **`bd init --proxied-server` has no preflight**: the missing-dolt error arrives after `.beads/` is created (`cmd/bd/init_proxied_server.go:137` vs `:151`).
6. **Storage-format compatibility is entirely undocumented and unchecked** — `dolt version`'s `database storage format:` line is explicitly discarded, and no code relates the go.mod pseudo-version to a CLI version.</result>
